## Database Overview

The FoodEase API uses a **PostgreSQL** database with **100+ entities** organized into logical domains:

| Domain | Purpose | Key Tables |
|--------|---------|-----------|
| **Restaurant Management** | Multi-tenant setup | Restaurant, RevenueCenter, RestaurantSetting |
| **Menu & Items** | Product catalog | Item, ItemClass, ItemParent, ItemPackage |
| **Recipes & Composition** | Item recipes | ItemRecipe, RecipeItem, ItemRecipeComponent |
| **Ordering System** | Order processing | Order, ItemOrder, OrderCharge, OrderPaymentChannel |
| **Inventory** | Stock management | StockTransfer, StockTake, ItemLocation, StockLog |
| **Purchasing** | Supplier orders | PurchaseOrder, PurchaseReceipt, Vendor |
| **Payments** | Financial transactions | OrderPaymentChannel, Transaction, RefundLog |
| **Users & Staff** | Access control | Staff, BaseUser, UserRole, CustomRole, CustomClaim |
| **Pricing** | Price management | PriceList, PriceBook, ItemPrice |
| **Reports & Analytics** | Data analysis | Report, FoodCostReport, ShiftReport |
| **Communications** | Messaging | WhatsappAccount, Newsletter, CustomChannels |
| **Additional** | Supporting features | Loyalty, Reservation, Blog, Session |

## Core Entities

### 🏢 RESTAURANT DOMAIN

#### Restaurant (Root Entity)
```
PK: Id (string)
Properties:
  - Code
  - ContactNumber
  - Email
  - BusinessId
  - KDSEnabled (Kitchen Display System)
  - TaxExclusive
  - RestaurantType
  - CountryCode
  - PayoutType
  - PayoutEnabled
```

**Relationships:**
- 1:N → RevenueCenter (one restaurant has many revenue centers)
- 1:N → Staff (one restaurant has many staff)
- 1:N → Item (one restaurant has many items)
- 1:N → Vendor (one restaurant has many vendors)
- 1:N → Order (one restaurant has many orders)
- 1:N → StockTeams
- 1:N → BannerImages
- 1:N → MobileImages
- 1:N → FeatureItems
- 1:N → OpeningHours
- 1:1 → RestaurantSetting

#### RevenueCenter (Store/Branch)
```
PK: Id (string)
FK: RestaurantId
Properties:
  - Name
  - Logo
  - PhoneNumber
  - State
  - Address
  - PickupAvailable
  - StockControl
  - PayoutAccountNumber
  - PayoutBankCode
```

**Relationships:**
- N:1 ← Restaurant
- 1:N → Table (one revenue center has many tables)
- 1:N → Order (one revenue center has many orders)
- 1:N → ItemRevenueCenter (junction table)
- 1:N → ClassRevenueCenter (junction table)
- 1:N → TaxRevenueCenter (junction table)
- 1:N → ChargeRevenueCenter (junction table)
- 1:N → RevCenterArea (preparation areas)
- 1:N → DeviceToken

#### RestaurantSetting
```
PK: Id (string)
FK: RestaurantId
Properties:
  - MinOrderAmount
  - DeliveryFee
  - TaxRate
  - PaymentMethods
  - ReceiptFormat
  - Currency
```

**Relationships:**
- 1:1 ← Restaurant

### 👥 USER & AUTHENTICATION DOMAIN

#### BaseUser (Identity User)
```
PK: Id (string)
Properties:
  - Email
  - PhoneNumber
  - FirstName
  - LastName
  - CreatedAt
  - UpdatedAt
  - IsActive
```

**Relationships:**
- 1:N → Staff (one user can be one staff member)
- 1:N → UserRole (junction table)
- 1:N → CustomClaim (custom claims for authorization)

#### Staff
```
PK: Id (string)
FK: RestaurantId, RevenueCenterId, UserId, RoleId
Properties:
  - FirstName
  - LastName
  - Email
  - PhoneNumber
  - RoleName
  - HashedPassword
  - HashedPin
  - Driver (boolean)
  - IdNumber
```

**Relationships:**
- N:1 ← Restaurant
- N:1 ← RevenueCenter
- N:1 ← BaseUser
- N:1 ← UserRole
- N:1 ← ItemPreparationArea
- 1:N → Order (as CreatedBy, Driver, PaymentBy, VoidedBy)

#### UserRole
```
PK: Id (string)
FK: UserId
Properties:
  - RoleName
  - Permissions
```

**Relationships:**
- N:1 ← BaseUser
- 1:N → RoleClaim

#### CustomRole, CustomClaim
```
Used for granular permission control
- CustomRole: Role definitions
- CustomClaim: Custom permission claims
```

### 🍔 ITEM & MENU DOMAIN

#### Item (Main Product)
```
PK: Id (string)
FK: RestaurantId, ItemClassId, TaxId, UnitOfMeasurementId
Properties:
  - Name
  - ShortName
  - Description
  - ImageUrl
  - SellingPrice
  - CostPrice

  - IsTransformable
  - IsVariablePrice
```

**Relationships:**
- N:1 ← Restaurant
- N:1 ← ItemClass
- N:1 ← Tax
- N:1 ← UnitOfMeasurement (selling UOM)
- N:1 ← UnitOfMeasurement (inventory UOM)
- 1:N → ItemVendor (junction)
- 1:N → ItemSource (purchasing info)
- 1:N → ItemLocation (storage locations)
- 1:N → ItemRevenueCenter (junction)
- 1:N → ItemComponent (item modifiers/toppings)

- 1:N → RecipeParent (items that contain this item)

#### ItemClass (Category)
```
PK: Id (string)
FK: RestaurantId
Properties:
  - Name
  - Code
  - Description
  - Sequence
```

**Relationships:**
- N:1 ← Restaurant
- 1:N → Item
- 1:N → ClassRevenueCenter (junction)
- Used in ItemOrder for categorization

#### ItemParent
```
Represents a parent item/group
FK: RestaurantId, ItemClassId, TaxId
```

**Relationships:**
- N:1 ← Restaurant
- 1:N → Item (parent contains multiple items)
- 1:N → ItemRecipe (parent's recipes)
- 1:N → ItemPrice (different prices for parent)
- 1:N → ItemSource (parent's sources)

#### ItemPackage (Bundle/Combo)
```
PK: Id (string)
FK: RestaurantId
Properties:
  - Name
  - Price
  - Description
  - Status
```

**Relationships:**
- N:1 ← Restaurant
- 1:N → ItemPackageSource
- Contains multiple items as a bundle

#### RecipeParent
```
Groups items that share recipes
FK: RestaurantId, ItemClassId, TaxId
```

**Relationships:**
- N:1 ← Restaurant
- 1:N → Item (items in this recipe)
- 1:N → ItemRecipe

### 🛒 ORDER DOMAIN

#### Order (Main Order)
```
PK: Id (string)
FK: RestaurantId, RevenueCenterId, TableId, SessionId, DiscountCodeId, TransactionId, SourceId, PriceListId
Properties:
  - GuestCount
  - TotalAmount
  - OrderStatus (Created, Pending, Ready, Completed, Cancelled)
  - SalesChannel (Dine-In, Takeout, Delivery, Online)
  - OrderType
  - ServiceType
  - IsPaid
  - IsVoid
  - HasRefunds
  - IsRefundOrder
  - IsSplitOrder
  - Tip
  - Change
  - MemberPhoneNo
  - MemberId
  - CreatedAt
  - PaidAt
```

**Relationships:**
- N:1 ← Restaurant
- N:1 ← RevenueCenter
- N:1 ← Table
- N:1 ← Session
- N:1 ← DiscountCode
- N:1 ← Source (sales channel source)
- N:1 ← PriceList
- 1:N ← Staff (CreatedBy, Driver, PaymentBy, VoidedBy)
- 1:N → ItemOrder (items in order)
- 1:N → OrderCharge (charges/fees)
- 1:N → OrderPaymentChannel (payment methods)
- 1:N → OrderTax (taxes applied)
- 1:N → CustomOrderChannel
- 1:N → OrderLog (audit trail)
- 1:1 → OrderTransaction

#### ItemOrder (Order Items)
```
PK: Id (string)
FK: OrderId, ItemClassId

  - Price

```

**Relationships:**
- N:1 ← Order


**Relationships:**
- N:1 ← Order

#### OrderPaymentChannel
```
PK: Id (string)
FK: OrderId
Properties:

  - Status
```

**Relationships:**
- N:1 ← Order

#### OrderTax

**Relationships:**

```

  - Status
```

**Relationships:**


## Detailed Entity Relationships

### 1. Restaurant → RevenueCenter → Order → ItemOrder

```
Restaurant (1:N) ← → RevenueCenter (1:N) ← → Order (1:N) ← → ItemOrder
```

**Description**: A restaurant has multiple revenue centers (stores/branches). Each revenue center can have multiple orders. Each order contains multiple items (ItemOrder).

**Example**:
```
Restaurant: "ChowDeck Lagos"
└── RevenueCenter: "Marina Branch"
    └── Order: "ORD-20260202-001"
        └── ItemOrder: "Jollof Rice x2"
        └── ItemOrder: "Fried Chicken x1"
```

### 2. Item → ItemClass → Restaurant

```
Item (N:1) ← → ItemClass (N:1) ← → Restaurant
```

**Description**: Items belong to restaurants and are categorized by ItemClass.

**Example**:
```
Restaurant
└── ItemClass: "Main Courses"
    └── Item: "Jollof Rice"
    └── Item: "Fried Rice"
```

### 3. Item → ItemRecipe → RecipeItem

```
Item (1:N) ← → RecipeItem (N:1) ← → ItemRecipe
```

**Description**: An item's recipe is defined by ItemRecipe. RecipeItem links items that make up that recipe.

**Example**:
```
ItemRecipe: "Jollof Rice Recipe"
└── RecipeItem: (Quantity: 2kg, Item: "Rice")
└── RecipeItem: (Quantity: 1L, Item: "Tomato Sauce")
└── RecipeItem: (Quantity: 500g, Item: "Pepper")
```

### 4. Item → ItemVendor → Vendor

```
Item (1:N) ← → ItemVendor (N:1) ← → Vendor
```

**Description**: Items can be sourced from multiple vendors. ItemVendor junction table tracks which vendors supply which items.

**Example**:
```
Item: "Rice"
├── ItemVendor: (Vendor: "Ahmed Supplies", UnitPrice: ₦5000)
├── ItemVendor: (Vendor: "Gold Foods", UnitPrice: ₦4800)
└── ItemVendor: (Vendor: "Quality Grains", UnitPrice: ₦5200)
```

### 5. Vendor → PurchaseOrder → ItemPurchaseRequest

```
Vendor (1:N) ← → PurchaseOrder (1:N) ← → ItemPurchaseRequest
```

**Description**: Purchase orders are placed with vendors for specific items.

**Example**:
```
Vendor: "Ahmed Supplies"
└── PurchaseOrder: "PO-001"
    ├── ItemPurchaseRequest: (Item: "Rice", Qty: 50kg, Price: ₦250,000)
    ├── ItemPurchaseRequest: (Item: "Oil", Qty: 20L, Price: ₦80,000)
    └── ItemPurchaseRequest: (Item: "Salt", Qty: 10kg, Price: ₦5,000)
```

### 6. PurchaseOrder → PurchaseReceipt → ItemPurchaseReceipt

```
PurchaseOrder (1:N) ← → PurchaseReceipt (1:N) ← → ItemPurchaseReceipt
```

**Description**: When items are received, they're recorded in PurchaseReceipt and linked back to PurchaseOrder.

**Example**:
```
PurchaseOrder: "PO-001" (Total: ₦335,000)
└── PurchaseReceipt: "REC-001" (Received: 2026-02-02)
    ├── ItemPurchaseReceipt: (Item: "Rice", Qty: 50kg, Received: 50kg) ✓
    ├── ItemPurchaseReceipt: (Item: "Oil", Qty: 20L, Received: 19.5L) ⚠️
    └── ItemPurchaseReceipt: (Item: "Salt", Qty: 10kg, Received: 10kg) ✓
```

### 7. StockTransfer → StockTransferReceipt

```
StockTransfer (1:N) ← → StockTransferReceipt
```

**Description**: Transfers stock from one location to another, with receipts confirming receipt.

**Example**:
```
StockTransfer: "ST-001" (From: Central Store, To: Marina Branch)
└── StockTransferReceipt: (Date: 2026-02-02, Status: Received)
    ├── Item: "Rice" - 50kg transferred
    ├── Item: "Oil" - 10L transferred
    └── Item: "Pepper" - 5kg transferred
```

### 8. Order → OrderPaymentChannel & Transaction

```
Order (1:N) ← → OrderPaymentChannel
Order (1:1) ← → OrderTransaction (1:N) ← → RefundLog
```

**Description**: Orders track payment methods and transactions, with refund history.

**Example**:
```
Order: "ORD-001" (Total: ₦25,000)
├── OrderPaymentChannel: (Card, ₦20,000)
├── OrderPaymentChannel: (Cash, ₦5,000)
└── OrderTransaction
    ├── TransactionId: "TRX-001"
    ├── Status: "Completed"
    └── RefundLog: (Amount: ₦2,000, Reason: "Partial refund", Date: 2026-02-02)
```

### 9. Order → OrderCharge

```
Order (1:N) ← → OrderCharge (N:1) ← → ChargeType
```

**Description**: Orders can have additional charges like delivery fees, service charges, etc.

**Example**:
```
Order: "ORD-001"
├── OrderCharge: (ChargeType: "Delivery", Amount: ₦2,000)
├── OrderCharge: (ChargeType: "Service", Amount: ₦1,000)
└── OrderCharge: (ChargeType: "Packaging", Amount: ₦500)
```

### 10. StockTake → ItemStockTake

```
StockTake (1:N) ← → ItemStockTake (N:1) ← → Item
```

**Description**: Physical inventory counts with variance tracking.

**Example**:
```
StockTake: "ST-COUNT-001" (Date: 2026-02-02)
├── ItemStockTake: (Item: "Rice", Expected: 100kg, Counted: 98kg, Variance: -2kg)
├── ItemStockTake: (Item: "Oil", Expected: 50L, Counted: 50L, Variance: 0L) ✓
└── ItemStockTake: (Item: "Salt", Expected: 20kg, Counted: 22kg, Variance: +2kg)
```

### 11. Loyalty Program

```
Restaurant (1:N) ← → LoyaltyConfig
Customer (1:N) ← → Loyalty (N:1) ← → Restaurant
```

**Description**: Loyalty programs track customer points and rewards.

**Example**:
```
Restaurant: "ChowDeck Lagos"
└── LoyaltyConfig: (PointsPerPurchase: 1pt per ₦100, TierThresholds: Bronze>Silver>Gold)
    └── Customer: "John Doe"
        └── Loyalty: (Points: 5,000, Tier: "Silver", JoinDate: 2025-01-01)
```

### 12. Authorization Hierarchy

```
BaseUser (1:N) ← → UserRole (1:N) ← → RoleClaim
                                            ↑
                                      CustomClaim (N:1)
```

**Description**: Fine-grained authorization system.

**Example**:
```
BaseUser: "admin@restaurant.com"
└── UserRole: "Admin"
    ├── RoleClaim: (Permission: "CanViewReports")
    ├── RoleClaim: (Permission: "CanDeleteOrder")
    ├── RoleClaim: (Permission: "CanManageStaff")
    └── RoleClaim: (Permission: "CanApprovePurchaseOrder")
```
