How to Fix It
You have two main paths depending on whether you want to use the new .NET 9 native support or stay with the classic Swashbuckle setup.
Option 1: Use the new .NET 9 Native OpenAPI (Recommended) 
This is the modern approach. It removes the conflicting Swashbuckle generation logic but keeps the Swagger UI for visualization. 
Step 1: Remove builder.Services.AddSwaggerGen();.
Step 2: Ensure your NuGet package for Swashbuckle.AspNetCore.SwaggerUi is updated to the latest version.
Step 3: Use this configuration: 
csharp
var builder = WebApplication.CreateBuilder(args);

// Registers the new .NET 9 OpenAPI generator
builder.Services.AddOpenApi(); 

var app = builder.Build();

// Serves the openapi.json at /openapi/v1.json
app.MapOpenApi();

// Point Swagger UI to the NEW generated endpoint
app.UseSwaggerUI(options => {
    options.SwaggerEndpoint("/openapi/v1.json", "v1");
});

app.MapGet("/", () => Results.Ok("cool"));
app.Run();
Use code with caution.

Option 2: Revert to Full Swashbuckle
If you prefer the classic behavior, remove the new .NET 9 native components to avoid the conflict. 
Step 1: Remove builder.Services.AddOpenApi(); and app.MapOpenApi();.
Step 2: Use the standard Swashbuckle middleware: 
csharp
builder.Services.AddSwaggerGen();
// ...
app.UseSwagger(); // Generates the JSON at /swagger/v1/swagger.json
app.UseSwaggerUI(); // Automatically points to the /swagger/ endpoint
Use code with caution.
