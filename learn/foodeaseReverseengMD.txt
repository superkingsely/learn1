## Overview

**FoodEase** is a comprehensive food service management API built with **C# (.NET 6.0)** and follows a **layered architecture** pattern. It's a restaurant management system that handles orders, inventory, payments, loyalty programs, and more.

### What This API Does
- **Restaurant Management**: Multi-restaurant support with settings and configurations
- **Order Management**: Complete order lifecycle (creation, payment, delivery, refunds)
- **Inventory Management**: Stock tracking, transfers, purchases, and recipes
- **Payment Processing**: Integration with multiple payment gateways (Flutterwave, PayStack, Wema Bank, Nomba)
- **Loyalty Programs**: Customer loyalty and rewards management
- **Reporting**: Comprehensive reports (food costs, revenue, sales)
- **Notifications**: Email, WhatsApp, and SMS notifications
- **Background Jobs**: Hangfire for scheduled tasks and background processing

## Architecture

### 🏗️ Layered Architecture Pattern

```
┌─────────────────────────────────────────────────────────┐
│         API Layer (FoodEase.Presentation)              │
│  Controllers → HTTP Requests & Responses               │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│         Service Layer (Service + Service.Contracts)     │
│  Business Logic → Data Processing & Validation         │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│    Repository Layer (Repository + Repository.Contracts)│
│  Data Access → Database Operations                     │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│         Database Layer (PostgreSQL)                     │
│  Persistent Storage                                    │
└─────────────────────────────────────────────────────────┘
```

**Why This Architecture?**
- **Separation of Concerns**: Each layer has a specific responsibility
- **Maintainability**: Easy to locate and fix bugs
- **Testability**: Each layer can be tested independently
- **Scalability**: New features can be added without affecting existing code
- **Reusability**: Services can be reused across different controllers

## Key Components

### 1. **RepositoryContext** (EF Core DbContext)
Located in: `Repository/RepositoryContext.cs`

This is the bridge between your C# objects and the PostgreSQL database. It defines all the database tables as DbSets.

**What it does:**
- Manages database connections
- Defines all entity mappings
- Configures relationships between tables
- Handles migrations

**Example usage in repository:**
```csharp
public class OrderRepository : RepositoryBase<Order>
{
    public OrderRepository(RepositoryContext context) : base(context) { }
    
    public async Task<IEnumerable<Order>> GetAllOrders()
    {
        return await FindAll().ToListAsync();
    }
}
```

### 2. **ServiceManager** (Facade Pattern)
Located in: `Service/ServiceManager.cs`

Uses the **Facade Pattern** to simplify access to multiple services.

**What it does:**
- Provides single entry point to all services
- Uses Lazy<T> for lazy initialization (services loaded on first use)
- Reduces memory footprint by only loading needed services

**Usage in controllers:**
```csharp
public class OrderController : ControllerBase
{
    private readonly IServiceManager _service;
    
    public OrderController(IServiceManager service)
    {
        _service = service; // Single dependency injection
    }
    
    // Access any service through _service
    await _service.OrderService.GetAllOrders();
    await _service.ItemService.GetItemById(id);
    await _service.PaymentService.ProcessPayment(data);
}
```

### 3. **RepositoryManager** (Repository Facade)
Located in: `Repository/RepositoryManager.cs`

Similar to ServiceManager but for data access layer.

**What it does:**
- Provides access to all repositories
- Manages DbContext
- Handles database transactions

### 4. **AutoMapper Profiles**
Located in: `Service/Automapper/`

Configures object mapping from Entities → DTOs and vice versa.

**What it does:**
- Converts database entities to API DTOs
- Converts API requests to database entities
- Handles complex nested mappings

**Example:**
```csharp
// Request DTO → Entity
public class CreateOrderDto { ... }

// Entity → Response DTO
public class OrderDto { ... }

// Mapping configuration
CreateMap<CreateOrderDto, Order>();
CreateMap<Order, OrderDto>();
```

### 5. **Controllers**
Located in: `FoodEase.Presentation/Controllers/`

HTTP endpoints handling incoming requests.

**Controller Structure:**

## How It Works

### Request Lifecycle

```
1. HTTP Request arrives at Controller
   ↓
2. Controller receives and validates request
   ↓
3. Controller calls appropriate Service method
   ↓
4. Service:
   - Applies business logic
   - Validates data
   - Calls Repository for data access
   ↓
5. Repository:
   - Queries database using EF Core
   - Returns data
   ↓
6. Service processes returned data (mapping, filtering, etc.)
   ↓
7. Controller builds response
   ↓
8. HTTP Response sent to client
```

### Example: Creating an Order

```
Step 1: Request arrives
POST /api/v1/order/create
{
  "restaurantId": "rest-123",
  "revenueCenterId": "rc-456",
  "items": [...]
}

Step 2: OrderController.CreateOrder() receives request
- Validates CreateOrderDto
- Calls _service.OrderService.CreateOrder(dto)

Step 3: OrderService.CreateOrder() processes
- Validates business rules
- Maps DTO to Order entity
- Calls _repository.OrderRepository.CreateAsync(order)

Step 4: OrderRepository.CreateAsync()
- Adds order to DbContext
- Calls SaveChangesAsync()
- Returns created order

Step 5: Service builds response
- Maps entity to response DTO
- Returns to controller

Step 6: Controller returns response
{
  "success": true,
  "data": {
    "orderId": "ord-789",
    "status": "created",
    ...
  },
  "errors": []
}
```

## Authentication & Authorization

### How JWT Authentication Works

```
1. User Credentials
   ↓
2. Login Endpoint (/auth/login)
   - Validates credentials
   - Generates JWT token
   - Returns token to client
   ↓
3. Client stores JWT token
   ↓
4. Every API request includes JWT in header
   Authorization: Bearer {token}
   ↓
5. [Authorize] attribute validates token
   - Checks signature
   - Verifies expiration
   - Validates claims
   ↓
6. Request proceeds if valid, 401 if invalid
```

### Configuration
Located in: `foodapi/Extensions/Authentication.cs`

```csharp
// JWT settings from appsettings.json
var jwt = configuration.GetSection("JWT").Get<JWT>();

// Validation parameters
- SigningKey: Secret key for signing
- ValidateAudience: false (accept any audience)
- ValidateIssuer: false (accept any issuer)
- ValidateLifetime: true (check expiration)
```

### Authorization Policies
Located in: `foodapi/Extensions/Authorization.cs`

Define who can access what endpoints:
```csharp
// Example: Role-based access
[Authorize(Roles = "Admin")]
public async Task<IActionResult> AdminOnlyEndpoint() { ... }

// Example: Custom policy
```

```csharp
public interface IFeedbackRepository : IRepositoryBase<Feedback>
```

**3c. Implement Repository** (Repository/ModelRepositories/FeedbackRepository.cs)
```csharp
public class FeedbackRepository : RepositoryBase<Feedback>, IFeedbackRepository
{
    public FeedbackRepository(RepositoryContext context) : base(context) { }
    
    public async Task<IEnumerable<Feedback>> GetCustomerFeedback(string customerId)
    {
        return await FindByCondition(f => f.CustomerId == customerId)
            .OrderByDescending(f => f.CreatedAt)
            .ToListAsync();
    }
    
    public async Task<decimal> GetAverageRating(string restaurantId)
    {
        return await FindAll()
            .Join(_context.Orders, f => f.OrderId, o => o.Id, (f, o) => new { f, o })
            .Where(x => x.o.RestaurantId == restaurantId)
            .AverageAsync(x => x.f.Rating);
    }
}
```

**3d. Create Service Interface** (Service.Contracts/IFeedbackService.cs)
```csharp
public interface IFeedbackService
{
    Task<Result<FeedbackDto>> AddFeedback(CreateFeedbackDto dto);
    Task<Result<IEnumerable<FeedbackDto>>> GetCustomerFeedback(string customerId);
    Task<Result<decimal>> GetAverageRating(string restaurantId);
}
```

**3e. Implement Service** (Service/FeedbackService.cs)
```csharp
public class FeedbackService : IFeedbackService
{
    private readonly IRepositoryManager _repository;
    private readonly IMapper _mapper;
    
    public FeedbackService(IRepositoryManager repository, IMapper mapper)
    {
        _repository = repository;
        _mapper = mapper;
    }
    
    public async Task<Result<FeedbackDto>> AddFeedback(CreateFeedbackDto dto)
    {
        // Validate input
        if (dto.Rating < 1 || dto.Rating > 5)
            return Result<FeedbackDto>.Failure("Rating must be 1-5");
        
        // Map DTO to entity
        var feedback = _mapper.Map<Feedback>(dto);
        
        // Create in database
        await _repository.FeedbackRepository.CreateAsync(feedback);
        await _repository.SaveAsync();
        
        // Map back to DTO and return
        var feedbackDto = _mapper.Map<FeedbackDto>(feedback);
        return Result<FeedbackDto>.Success(feedbackDto);
    }
    
    public async Task<Result<IEnumerable<FeedbackDto>>> GetCustomerFeedback(string customerId)
    {
        var feedback = await _repository.FeedbackRepository.GetCustomerFeedback(customerId);
        var feedbackDtos = _mapper.Map<IEnumerable<FeedbackDto>>(feedback);
        return Result<IEnumerable<FeedbackDto>>.Success(feedbackDtos);
    }
}
```

**3f. Create Controller** (FoodEase.Presentation/Controllers/FeedbackController.cs)
```csharp

    {
        CreateMap<CreateFeedbackDto, Feedback>();
        CreateMap<Feedback, FeedbackDto>();
    }
}
```


#### Step 4: Follow Code Standards

**Async/Await Pattern**
```csharp
// ✅ GOOD
public async Task<Order> GetOrderAsync(string id)
{
    return await _repository.OrderRepository.GetByIdAsync(id);
}

// ❌ BAD
public Order GetOrder(string id)
{
    return _repository.OrderRepository.GetById(id).Result; // Blocks!
}
```

**Dependency Injection**
```csharp
// ✅ GOOD - Inject dependencies
public class OrderService
{
    private readonly IRepositoryManager _repository;
    
    public OrderService(IRepositoryManager repository)
    {
        _repository = repository;
    }
}

// ❌ BAD - Creating instances
public class OrderService
{
    private RepositoryManager _repository = new RepositoryManager();
}
```

**Error Handling**
```csharp
// ✅ GOOD
if (string.IsNullOrEmpty(dto.OrderId))
    return BadRequest(ResponseBuilder.BuildResponse(null, "Order ID is required"));

// ❌ BAD
var order = _service.GetOrder(dto.OrderId); // Could throw exception
```

**LINQ Usage**
```csharp
// ✅ GOOD - Use async LINQ
var orders = await _repository.FindByCondition(o => o.Status == "Pending")
    .OrderByDescending(o => o.CreatedDate)
    .ToListAsync();

// ❌ BAD - Loading all data then filtering
var allOrders = _repository.FindAll().ToList();
var orders = allOrders.Where(o => o.Status == "Pending").ToList();
```

## Key Code Patterns Used

### Pattern 1: Repository Pattern
Abstracts database access.

```csharp
// Interface
public interface IOrderRepository : IRepositoryBase<Order>
{
    Task<Order> GetByIdAsync(string id);
}

// Implementation
public class OrderRepository : RepositoryBase<Order>, IOrderRepository
{
    public async Task<Order> GetByIdAsync(string id)
    {
        return await FindByCondition(o => o.Id == id).FirstOrDefaultAsync();
    }
}

// Usage in service
var order = await _repository.OrderRepository.GetByIdAsync(id);
```

### Pattern 2: Dependency Injection
Constructor injection for loose coupling.

```csharp
public class OrderService : IOrderService
{
    private readonly IRepositoryManager _repository;
    private readonly IMapper _mapper;
    
    // Dependencies injected through constructor
    public OrderService(IRepositoryManager repository, IMapper mapper)
    {
        _repository = repository;
        _mapper = mapper;
    }
}
```

### Pattern 3: Lazy Loading
Load services only when needed.

```csharp
// In ServiceManager
private readonly Lazy<IOrderService> _orderService;

public IOrderService OrderService => _orderService.Value;

// Service created only on first access
_service.OrderService.GetAllOrders(); // Created here
```

### Pattern 4: DTO Pattern
Separate API contracts from database entities.

```csharp
// Database entity
public class Order : DbEntity
{
    // ... 20+ properties
}

// API request DTO
public class CreateOrderDto
{
    public string RestaurantId { get; set; }
    public List<OrderItemDto> Items { get; set; }
}

// API response DTO
public class OrderDto
{
    public string Id { get; set; }
    public string OrderNumber { get; set; }
    // Only necessary fields
}
```

### Pattern 5: Async/Await
All I/O operations are asynchronous.

```csharp
public async Task<List<Order>> GetOrdersAsync()
{
    return await _repository.OrderRepository
        .FindAll()
        .ToListAsync();
}
```

## Common Issues & Solutions

### Issue: Entity Not Saved to Database
**Cause**: Forgot to call `SaveAsync()` or `SaveChangesAsync()`

**Solution**:
```csharp
// Add item
await _repository.ItemRepository.CreateAsync(item);

// Don't forget this!
await _repository.SaveAsync();
```

### Issue: Circular Reference in Entity Relationships
**Cause**: Lazy loading of navigation properties causes infinite loops

**Solution**:
```csharp
// Use NoTracking for read-only queries
var orders = await _repository.OrderRepository
    .FindAll()
    .AsNoTracking()
    .ToListAsync();

// Or disable automatic lazy loading
context.ChangeTracker.LazyLoadingEnabled = false;
```

### Issue: Slow Database Queries
**Cause**: N+1 queries or missing indexes

**Solution**:
```csharp
// Use .Include() to eager load related data
var orders = await _repository.OrderRepository
    .FindAll()
    .Include(o => o.Items)
    .Include(o => o.PaymentChannels)
    .ToListAsync();

// Add database indexes on frequently queried columns
[Index(nameof(OrderNumber))]
[Index(nameof(RestaurantId))]
public class Order : DbEntity { }
```
